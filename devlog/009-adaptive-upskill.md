# 009 · Adaptive Upskill — 가르치기 전에 먼저 측정하는 학습 스킬

> AI에게 "X 가르쳐 줘"라고 하면 처음부터 시작한다. 내가 뭘 아는지 모르니까
> 물어보고 믿거나, 그냥 짐작한다. 그래서 필요 없던 한 시간을 쓰고,
> 정작 구멍 난 곳은 그대로 남고, 세션이 끝나면 진도가 증발한다.

- **분야:** AI 에이전트 스킬 · 학습 시스템 · Agent Skills 표준
- **위험도:** Tier 1 (로컬 전용, 서버·계정·결제 없음)
- **상태:** v0.3 공개 — https://github.com/aslla77/adaptive-upskill (MIT)

## 왜 만들었나

구직용으로 [MadsLorentzen/ai-job-search](https://github.com/MadsLorentzen/ai-job-search)를 쓰고 있었다. 그 안에 `upskill` 스킬이 있다. 공고들을 훑어서 내 프로필과 대조하고 부족한 스킬을 뽑아 학습 계획을 만들어 준다.

그런데 딱 거기까지다. **부족한 걸 알려주고 끝난다.** 배우는 건 알아서 해야 한다.

그래서 그냥 AI한테 배우면 되지 않나 싶었는데, 해 보면 세 가지가 걸린다.

- **내 수준을 안 묻는다.** 물어도 자기보고를 그대로 믿는다. "저 중급이에요"는 증거가 아니다.
- **세션이 끝나면 사라진다.** 다음에 다시 물으면 처음부터다.
- **"이제 마스터했다"는 판정에 근거가 없다.** 물어볼 때마다 답이 다르다.

세 번째가 제일 문제였다. 같은 모델에게 "내 파이썬 실력을 0에서 1로 평가해 줘"라고 하면 오늘 0.62, 내일 0.74가 나온다. 그 숫자 위에 학습 계획을 세우면 계획도 같이 흔들린다.

## 무엇을 만들었나

한 문장으로: **LLM은 가르치고, 프로그램이 기록·채점·상태관리를 한다.**

```
LLM      문항 생성, 루브릭 채점, 설명, 레슨 저작
Python   점수 정규화, 숙련도 계산, 진단 종료 판정,
         선수지식 게이트, 계획 순서, 상태 파일 갱신
```

모든 숫자는 append-only 증거 파일 위의 순수 산술에서 나온다. 파생 상태를 지워도 증거만 있으면 똑같이 복원된다.

그 위에 얹은 것들.

- **적응형 최소 진단** — 5문항으로 시작해 애매한 곳만 한 문항씩 더 묻고, 배치가 가능해지면 멈춘다. 언제 멈출지는 코드가 계산한다. 픽스처 실측으로 6~7문항.
- **선수지식이 점수를 이긴다** — 파일 입출력에서 0.83을 받아도 그 밑의 자료구조가 0.0이면 파일 입출력은 잠긴다.
- **건너뛴 것에 근거를 붙인다** — 각 모듈에 왜 여기 있는지, 건너뛴 모듈에 무슨 증거로 건너뛰었는지. 감사할 수 없는 계획은 피드백이 아니라 성적표다.
- **"모름"과 "약함"을 구분한다** — 증거가 없으면 0이 아니라 `unknown`. 어려운 문제를 맞혀서 함의된 개념은 `assumed-ok` — 행동해도 되는 추정이지 입증된 실력이 아니다.

## 만드는 과정

**과목마다 숙련의 뜻이 다르다는 걸 중간에 알았다.** 처음엔 하나의 규칙으로 다 다루려 했는데, 언어 학습에서 무너졌다. 그래서 유형을 셋으로 나눴다.

| | 도구·구현형 | 개념·모델형 | 언어·습득형 |
|---|---|---|---|
| 숙련이란 | 만들 수 있다 | 새 상황에 옮긴다 | 빠르고 정확하게, 다음 주에도 |
| 한 번 맞히면 | 대체로 인정 | 전이 문항 하나 더 | **인정 안 됨** |

마지막 줄이 핵심이다. 어제 맞힌 단어를 오늘 못 쓰면 못 하는 거다. 그래서 언어는 간격 반복 증거 없이는 최고 등급에 도달할 수 없게 **코드로 막았다.** 문서에만 적으면 우회된다.

**PyTorch를 테스트하다 실행 환경이라는 구멍을 발견했다.** 스킬이 "실습 = 로컬 파일 + 테스트"를 암묵적으로 가정하고 있었는데, PyTorch는 GPU가 필요하고 맥에서 제대로 안 돈다. 파이토치를 배우는 사람은 CUDA 설치와 싸울 게 아니라 MNIST를 돌려야 한다.

그래서 실행 환경을 목표의 일부로 만들었다 — `none` / `local` / `notebook` / `colab`. **`none`이 예외 처리가 아니라 정식 값이다.** 일본어와 순수 수학은 도구가 필요 없고, 그 앞에 설치 단계를 놓으면 첫 세션이 통째로 날아간다.

Colab에서도 결정론을 잃지 않는 방법은 고정 채점 셀이다. 노트북 마지막에 자동 채점 셀이 들어가고 `UPSKILL_RESULT <task> 2/3` 한 줄을 출력한다. 학습자는 그 줄만 붙여넣고, **파싱도 스크립트가 한다** — 화면의 숫자를 읽어 옮기는 것도 판단이 샐 수 있는 지점이라서.

**터미널에서 일본어를 배울 수 없다는 것도 써 보고 알았다.** CJK 폭 계산이 틀리고, 후리가나는 아예 표현이 안 되고, 폰트에 없는 글자는 네모가 된다. 그래서 언어 과목은 HTML 페이지로 렌더한다.

비용이 걱정이라 **모델이 HTML을 쓰지 않게** 했다. 고정 셸을 한 번 만들어 두고, 매 레슨은 작은 JSON만 만들어 스크립트가 합친다. 실측으로 레슨당 2.0KB JSON 대 15.8KB HTML — **7.9배** 차이고, 13.8KB짜리 셸은 최초 1회다.

## 실제로 써 보고서야 나온 것들

시뮬레이션과 픽스처로는 안 나오던 것들이 실사용에서 줄줄이 나왔다.

- **일본어 자판이 없어서 답을 칠 수가 없었다.** 로마자로 쳤더니 오답 처리됐다. 그래서 가나 답을 쓰면 로마자 읽기도 자동으로 받게 했다. 저자는 답을 한 번만 쓴다. `ねが`는 `nega`를 받고, `コーヒー`는 `koohii`·`ko-hi-`·`kōhī`를 다 받는다.
- **문장을 정답 대조로 채점하면 안 된다.** 「カフェに」와 「カフェで」의 차이가 그 레슨의 전부인데, 문자열 비교는 "틀렸다"밖에 못 한다. 배우는 게 없다. 그래서 세 어절이 넘는 답은 렌더 단계에서 거부하고 루브릭 채점으로 보낸다. 저자가 기억하기를 믿지 않고 강제했다.
- **레슨 생성이 오래 걸려서 매번 기다렸다.** 그래서 현재 레슨을 푸는 동안 다음 레슨을 백그라운드에서 쓰게 했다. 깊이는 1이다 — 체크포인트를 틀리면 계획이 뒤집히고 그 이상 미리 만든 건 대부분 버려진다.
- **듣기는 측정 불가라고 문서에 적어 뒀는데 틀렸다.** 실제 세션이 `say`로 오디오를 만들어 청해 문항을 냈고, 오답 선택지마다 어떤 청취 오류를 잡는지까지 설계돼 있었다. 문서를 고쳤다. 말하기는 여전히 불가다.

버그도 돌려 봐야 나왔다. 함의 증거가 이미 더 높은 직접 증거를 끌어내려 등급을 강등시켰고, 노트북 채점 셀은 `%` 이스케이프가 깨져 실행할 때마다 터졌고, 선행 제작은 **아직 차례가 안 온 멀쩡한 레슨을 버렸다.** 셋 다 테스트가 잡았다.

## 배운 점

- **기다림은 기능 결함이다.** 정확도를 아무리 올려도 매 모듈마다 스피너를 보면 안 쓴다. 선행 제작은 성능 최적화가 아니라 이 도구가 쓰이느냐 마느냐의 문제였다.
- **"틀렸다"만 말하는 채점은 채점이 아니다.** 무엇이 왜 틀렸는지 말할 수 없다면 애초에 그 방식으로 채점하면 안 된다. 정답 대조를 못 쓰는 자리를 인정하는 게 정확도를 지키는 길이었다.
- **설치 마찰이 학습을 죽인다.** 일본어 자판을 깔아야 첫 레슨을 시작할 수 있다면, 첫 레슨은 시작되지 않는다.
- **문서로 적은 규칙은 우회된다.** 언어 과목의 간격 반복 요구, 문장의 루브릭 채점, 스킬 이식성 제약 — 전부 코드로 막고 나서야 지켜졌다.
- **직접 브라우저를 열어야 보이는 것이 있다.** 제목의 후리가나가 대괄호째 노출되고 `**볼드**`가 별표째 나오는 건 테스트로 안 잡힌다.
- **모른다고 적어 둔 것도 틀릴 수 있다.** 듣기 측정이 그랬다. 제약을 적을 때도 근거가 필요하다.

## 아직 안 된 것

- **사람이 학습을 처음부터 끝까지 완주한 적이 없다.** 스크립트와 픽스처는 검증됐지만 장기 사용은 미검증이다.
- 임계값 `0.45 / 0.70 / 0.85`는 계획 순서를 정하려고 고른 설정값이다. 응답 데이터로 보정된 적 없고, 그렇게 표현하지 않는다.
- 자격증·암기형 과목 미지원, 말하기 측정 불가, 진도 대시보드 미구현.
