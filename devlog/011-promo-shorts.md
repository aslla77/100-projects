# 011 · 홍보 쇼츠 파이프라인 — 대본 한 장과 녹음 하나로 앱 소개 영상을 뽑는 실험

> 앱 한 개의 소개 쇼츠를 만드는 데 며칠이 걸리면, 앱 여섯 개의 홍보는 영영 밀린다.
> 대본 한 장과 목소리 녹음 하나에서 텍스트 카드·앱 실화면·자막의 타이밍을 자동으로 맞춰
> 한국어·영어 쇼츠 두 편을 뽑아내는 파이프라인을 만들어 보고 있다.

- **분야:** 영상 · 마케팅 자동화 · Python / ffmpeg / Whisper
- **위험도:** Tier 0 (로컬 도구 · 사용자 데이터 없음)
- **상태:** 실험 중 — 정식 프로젝트로 올리기 전 단계. 언제했지(#008) 소개 쇼츠 3편(한·영)을 산출했고, 같은 문제를 다른 방식으로 푼 앱 실화면 중심 파이프라인이 008 쪽에서 15개 언어로 자라났다.

## 왜 만들었나

앱은 스토어 제출까지 API 파이프라인으로 자동화해 뒀는데, 홍보 영상만 전부 손이었다.
앱이 여섯 개가 되자 이게 병목이 됐다 — 만들지 않으면 아무도 모르고, 만들자니 한 편에 며칠.

스토어 스크린샷을 "재료 + 절차"로 재현 가능하게 만들었던 것과 같은 방식으로 풀고 싶었다.
새 영상 한 편이 **대본 한 장 + 녹음 한 개**로 끝나야 한다. 목표는 나중에 다른 프로젝트에서도
쓸 수 있는 독립 스킬이지만, 먼저 실제 산출물로 검증한 뒤에 스킬로 올리기로 했다.

## 무엇을 만들었나

1. **정렬** — 녹음한 목소리를 Whisper로 받아 적어 단어 단위 타이밍을 얻고,
   대본의 각 줄과 문자열 유사도로 매칭해 줄마다 시작·끝 시각을 만든다.
2. **렌더** — 디노이즈, 긴 침묵을 0.3초로 줄이는 묵음 압축(줄인 만큼 타이밍을 자동 재계산),
   앱의 디자인 언어를 그대로 따른 텍스트 카드, 사진, 느린 줌 모션.
3. **앱 실화면 합성** — 시뮬레이터에서 녹화한 실제 앱 화면을 카드 위에 얹는다.
   플랫폼의 추천 가이드가 텍스트만으로 채운 영상에 불리하다고 명시해서, 실화면을 중심에 뒀다.
4. **TTS 대안** — 줄 단위로 음성을 생성하면 타이밍이 정확해 정렬 단계가 필요 없다.
   영어판은 전부 이 경로로 만든다.

산출물은 챕터마다 `ko`/`en` 영상 한 편씩과 게시용 캡션 문서다.
지금까지 언제했지의 "Done List" 시리즈에서 3편(진전의 원리·자이가르닉·앤드리슨)을 냈다.

## 만드는 과정

- **리서치 먼저.** 플랫폼별 공식 가이드와 벤치마크를 먼저 읽고 원칙을 정했다 —
  훅은 첫 3~6초에 승부, 광고성 영상은 20~30초대, 워터마크 금지, 비즈니스 계정의 음악은
  플랫폼이 제공하는 라이브러리만.
- **시뮬레이터 녹화는 함정이 있었다.** 시뮬레이터 화면 녹화는 바뀐 프레임만 기록해서
  시킹으로 훑으면 정지 화면처럼 보인다. 전체 프레임을 덤프해서 확인해야 했다.
  화면 좌표 클릭은 창 위치 + 타이틀 바 높이 + 포인트×배율로 계산하고, 베젤은 끄고 찍는다.
- **영어판은 화면 속 데이터도 영어여야 한다.** 데모 데이터를 언어별로 치환하고
  원본은 백업해 뒀다.

## 갈라져 나간 두 번째 길 — 앱 실화면 중심 영상

011 실험이 "내 목소리 + 카드"에 가까웠다면, 008의 홍보 도구(promo-kit)는 방향이 달랐다. 앱을 **직접 조작해 찍고**, 그 화면 위에 자막과 장면 전환만 얹는다.

- **촬영을 코드로.** 시뮬레이터 좌표를 눌러 찍던 방식을 버리고, Flutter 통합 테스트가 위젯을 이름으로 찾아 눌러 가며 촬영한다. 언어가 바뀌어도 깨지지 않고, 강조할 요소의 위치도 앱이 직접 알려 준다. 촬영이 화면보다 늦게 따라와 다음 장면이 찍히는 일은 "찍었다"는 신호 파일을 주고받는 핸드셰이크로 막았다.
- **렌더는 Remotion.** 힌디어·아랍어·태국어처럼 글자 조합이 복잡한 언어도 브라우저 엔진이 조판하므로 Pillow로는 안 되던 문자가 맞게 나온다. 버튼 이름은 앱의 번역 파일에서 그대로 가져와, 영상이 가리키는 버튼과 실제 앱 화면이 어긋나지 않게 했다. 못 채우면 렌더가 실패한다.
- **권리 정리를 도구에 넣었다.** 배경음악은 사인파와 잡음으로 직접 합성하고, 글꼴은 OFL만, 스토어 배지·기기 이미지는 쓰지 않는다. 자산마다 출처를 표로 남겨 검수 없이도 쓸 수 있게 했다. App Store 미리보기에는 앱 실녹화만 허용된다는 규정이 있어 그 용도의 영상은 기기 틀·카드를 뺀 별도 렌더로 만들었다.
- **15개 언어 일괄 렌더.** 새 언어 문구는 번역 후 별도 모델로 교차 검수를 거쳤고, 촬영은 언어마다 시뮬레이터를 켜고 끄는 순서로 했다.

### 손으로 자른 영상을 여섯 번 고치며

실녹화를 직접 편집한 한국어판을 기준으로 TTS 음성을 입혀 보며 취향을 좁혔다.

- 검은 배경은 "미감이 없다"는 이유로 앱 아이콘 톤의 밝은 배경으로 바꿨고, 직접 그린 아이폰 테두리는 Apple의 마케팅 가이드라인(제품 이미지를 있는 그대로 쓸 것, 기기 흉내 금지)에 걸려 쓰지 않기로 했다.
- 속도가 가장 큰 논점이었다. 장면 길이를 "대사 + 0.35초"로 맞추고 1.2배속으로 돌리면 이탈은 적을 것 같았지만 들어 보니 너무 빨랐다. 1.1배속에 촬영분 배속을 완화한 쪽이 지금의 합의선이다.
- 음성은 Gemini TTS로 만들었다. 대사는 개발자가 앱을 보여 주는 1인칭 튜토리얼 톤으로 썼다.
- 이 판은 번체 중국어와 영어로 확장했다. 번체판은 그 지역 생활 맥락의 더미 데이터와 생성 사진 14장으로 새로 촬영했고, 영어판은 앱 이름 발음을 음성 인식으로 철자 비교해 원 표기를 유지했다. 영어는 원래 말이 빨라 배속을 걸지 않았다.

### 시뮬레이터 촬영의 함정

- 처음 키보드를 띄우면 '밀어서 입력' 안내가 화면을 덮는다. 설정 값으로 미리 막아 둔다.
- 재부팅 직후 첫 키보드는 몇 초 늦게 뜨므로 한 번 띄웠다 내린 뒤 녹화한다.
- 자판 언어를 바꾸려면 시뮬레이터를 재부팅해야 하고, 스크립트가 백업과 원복을 맡는다.
- **촬영 중에 다른 CPU 작업(음성 인식, 렌더)을 돌리지 않는다.** 영어판 첫 촬영이 음성 인식과 겹쳐 대화상자가 8초씩 늦게 뜨는 바람에 통째로 버렸다.
- ffmpeg의 `fade=d=0`은 "페이드 없음"이 아니라 25프레임 페이드가 걸린다. 필터를 빼야 한다.

## 배운 점

- **애드립이 대본보다 낫다.** 뼈대만 주고 말하게 했을 때 문장이 살아났다.
  대본은 순서와 핵심 문구만 고정한다.
- **잔향은 후처리로 못 지운다.** 디노이즈는 되지만 울림은 남는다. 녹음 환경이 우선이다.
- **홍보 훅에서 앱을 부정하지 않는다.** "앱이 아니라 종이였다" 같은 훅은 반전처럼 보이지만
  제품을 깎는다. 문제 공감으로 열고, 도구는 해결로 등장시킨다.
- **지어낸 경험담 금지는 영상에도 그대로다.** 실제 경험·질문형·상태 묘사만 쓴다(#008에서 세운 원칙).
- **기능을 나열하지 않는다.** 영상 하나에 메시지 하나. 기능이 많으면 짧은 시리즈로 나누거나 이야기 속 사건으로 넣는다. 자막 줄 끝의 마침표·쉼표는 뺀다.
- **새 홍보물은 기존 파이프라인을 무심코 재사용하지 않는다.** 앱마다 전할 말이 다르니, 도구를 재사용하기 전에 그 앱에 맞는 방식부터 다시 조사한다.
- **영상 속 데이터는 번역이 아니라 나라별로 새로 짠다.** 영어판 화면에 한국어식 일상이 번역만 되어 있으면 어색하다.
- **재료와 절차를 저장소에 남긴다.** 중간 산출물을 전부 작업 폴더에 두니
  새 챕터는 스크립트 하나를 복제해 대본만 바꾸면 됐다.
