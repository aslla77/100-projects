# 011 · 홍보 쇼츠 파이프라인 — 대본 한 장과 녹음 하나로 앱 소개 영상을 뽑는 실험

> 앱 한 개의 소개 쇼츠를 만드는 데 며칠이 걸리면, 앱 여섯 개의 홍보는 영영 밀린다.
> 대본 한 장과 목소리 녹음 하나에서 텍스트 카드·앱 실화면·자막의 타이밍을 자동으로 맞춰
> 한국어·영어 쇼츠 두 편을 뽑아내는 파이프라인을 만들어 보고 있다.

- **분야:** 영상 · 마케팅 자동화 · Python / ffmpeg / Whisper
- **위험도:** Tier 0 (로컬 도구 · 사용자 데이터 없음)
- **상태:** 실험 중 — 정식 프로젝트로 올리기 전 단계. 언제했지(#008) 소개 쇼츠 3편(한·영)을 산출했다.

## 왜 만들었나

앱은 스토어 제출까지 API 파이프라인으로 자동화해 뒀는데, 홍보 영상만 전부 손이었다.
앱이 여섯 개가 되자 이게 병목이 됐다 — 만들지 않으면 아무도 모르고, 만들자니 한 편에 며칠.

스토어 스크린샷을 "재료 + 절차"로 재현 가능하게 만들었던 것과 같은 방식으로 풀고 싶었다.
새 영상 한 편이 **대본 한 장 + 녹음 한 개**로 끝나야 한다. 목표는 나중에 다른 프로젝트에서도
쓸 수 있는 독립 스킬이지만, 먼저 실제 산출물로 검증한 뒤에 스킬로 올리기로 했다.

## 무엇을 만들었나

1. **정렬** — 녹음한 목소리를 Whisper로 받아 적어 단어 단위 타이밍을 얻고,
   대본의 각 줄과 문자열 유사도로 매칭해 줄마다 시작·끝 시각을 만든다.
2. **렌더** — 디노이즈, 긴 침묵을 0.3초로 줄이는 묵음 압축(줄인 만큼 타이밍을 자동 재계산),
   앱의 디자인 언어를 그대로 따른 텍스트 카드, 사진, 느린 줌 모션.
3. **앱 실화면 합성** — 시뮬레이터에서 녹화한 실제 앱 화면을 카드 위에 얹는다.
   플랫폼의 추천 가이드가 텍스트만으로 채운 영상에 불리하다고 명시해서, 실화면을 중심에 뒀다.
4. **TTS 대안** — 줄 단위로 음성을 생성하면 타이밍이 정확해 정렬 단계가 필요 없다.
   영어판은 전부 이 경로로 만든다.

산출물은 챕터마다 `ko`/`en` 영상 한 편씩과 게시용 캡션 문서다.
지금까지 언제했지의 "Done List" 시리즈에서 3편(진전의 원리·자이가르닉·앤드리슨)을 냈다.

## 만드는 과정

- **리서치 먼저.** 플랫폼별 공식 가이드와 벤치마크를 먼저 읽고 원칙을 정했다 —
  훅은 첫 3~6초에 승부, 광고성 영상은 20~30초대, 워터마크 금지, 비즈니스 계정의 음악은
  플랫폼이 제공하는 라이브러리만.
- **시뮬레이터 녹화는 함정이 있었다.** 시뮬레이터 화면 녹화는 바뀐 프레임만 기록해서
  시킹으로 훑으면 정지 화면처럼 보인다. 전체 프레임을 덤프해서 확인해야 했다.
  화면 좌표 클릭은 창 위치 + 타이틀 바 높이 + 포인트×배율로 계산하고, 베젤은 끄고 찍는다.
- **영어판은 화면 속 데이터도 영어여야 한다.** 데모 데이터를 언어별로 치환하고
  원본은 백업해 뒀다.

## 배운 점

- **애드립이 대본보다 낫다.** 뼈대만 주고 말하게 했을 때 문장이 살아났다.
  대본은 순서와 핵심 문구만 고정한다.
- **잔향은 후처리로 못 지운다.** 디노이즈는 되지만 울림은 남는다. 녹음 환경이 우선이다.
- **홍보 훅에서 앱을 부정하지 않는다.** "앱이 아니라 종이였다" 같은 훅은 반전처럼 보이지만
  제품을 깎는다. 문제 공감으로 열고, 도구는 해결로 등장시킨다.
- **지어낸 경험담 금지는 영상에도 그대로다.** 실제 경험·질문형·상태 묘사만 쓴다(#008에서 세운 원칙).
- **재료와 절차를 저장소에 남긴다.** 중간 산출물을 전부 작업 폴더에 두니
  새 챕터는 스크립트 하나를 복제해 대본만 바꾸면 됐다.
