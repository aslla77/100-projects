# 019 · 마팔오 — 아는 제품 뒤의 회사 이야기를 공시로 풀어내는 쇼츠 엔진

> 누구나 쓰는 제품인데, 그 회사가 실제로 무엇으로 돈을 버는지는 아무도 모른다.
> 공시 원문으로 **한 문장짜리 주장**을 세우고, 대본·영상·검수·업로드까지
> 사람 손을 거의 타지 않고 한 편을 뽑아내는 파이프라인을 만들었다.

- **분야:** 영상 자동화 · TypeScript · Remotion · LLM 파이프라인
- **위험도:** Tier 2 (외부 API·OAuth 토큰·공개 게시. 사용자 데이터 없음. 기업 이야기라 투자 권유 금지가 핵심 제약)
- **상태:** 제작·공개 운영 중 (쇼츠 중심에서 긴 영상 1편 + 거기서 뽑는 쇼츠 형식으로 전환 중)

## 왜 만들었나

예전에 만든 유튜브 자동 생산 파이프라인에서 채널 하나를 따로 떼어 다시
시작했다. 기존 쇼츠는 상단 헤더 고정에 작은 박스가 붙은 틀이었고, 검은 배경에
큰 숫자를 얹은 첫 시험작은 내용은 잘 뽑혔는데 **"PPT 같다"** 는 이유로
비주얼이 불합격이었다. 재시작의 목표는 두 가지였다.

1. "AI가 찍어낸 영상"이 아니라 **볼 이유가 있는 영상** — 수치는 공시 원문으로만,
   약점과 리스크도 말하고, 투자 권유는 하지 않는다.
2. 일을 사람이 거의 하지 않는 구조. 나는 **검수만** 하고, 촬영도 녹음도 하지 않는다.

시청자는 35~55세로 잡았다. "옛날에 많이 썼는데 지금은 뭐 하지?" 또는 "나 이거
지금 쓰는데 어떤 회사지?"로 끌리는 제품이 소재다. 제품을 입구로 쓰고, 공시를
출구로 쓴다.

## 무엇을 만들었나

- **에피소드 엔진** — 에피소드 폴더에 JSON 몇 개를 넣으면 검증 → 음성 합성 →
  청취 확인 → 믹스 → 프리뷰 → 렌더 → 프레임 검사 → 설명란 생성까지 단계별로
  돈다. 실패하면 그 단계에서 멈추고, `--from`/`--only`로 이어서 다시 돌린다.
- **검증기 묶음** — 숫자는 출처가 있어야 하고, 통화 단위가 맞아야 하고, 금지어와
  중복·템플릿 반복을 걸러낸다. 대본 구간과 장면 구간이 어긋나도 잡는다.
- **음성 받아쓰기 대조** — 합성한 음성을 음성 인식으로 다시 받아 써서 "반드시 들려야
  하는 낱말"이 실제로 들리는지 확인한다. 받침이 약해지는 정도의 비슷한 발음은
  통과시키고, 많이 다르면 두 번 다시 생성한 뒤 멈춘다.
- **준비 단계** — 조사 → 논지 → 대본 → 스토리보드 → 소재. 논지 단계는 공시 원문과
  사실 목록에서 후보 3개를 만들고, 인용문이 원문과 일치하는지, 증명 사실이 둘
  이상인지까지 검사한다.
- **화면 구성** — 매 컷 실사 풀블리드 + 반투명 유리 카드, 증권 앱 같은 시세 UI,
  실제 지도를 d3로 그려 카메라를 움직이는 장면, 제품 사진은 macOS 피사체 분리로
  배경을 오려낸 컷아웃. 장면마다 출처 한 줄이 들어간다.
- **업로드 CLI** — 비공개 예약 업로드, 유료 프로모션 표시, 재생목록 추가, 공개
  후 댓글까지 명령 하나씩. 비밀값은 로그에서 가려진다.
- **순위 특식** — 평소 파이프라인과 분리된 순위 영상(TOP5 등) 전용 경로.
- **긴 영상 조립기** — 11월 중순에 긴 영상 1편을 만들고 거기서 쇼츠 여러 편을
  뽑는 형식으로 넘어갔다. 긴 영상 조립·쇼츠 추출 스크립트를 에피소드 안에 뒀다.

## 만드는 과정

- **첫 시험작의 비주얼이 불합격이었다.** "내용은 미친 듯이 잘 뽑았는데 비주얼이
  영 아니다"라는 평이었다. 원인을 따져 보니 검은 배경 + 거대 숫자의 반복, 직접
  그린 SVG 아이콘, 제품을 진짜로 보여주지 않는 점이었다. 방향을 실사 풀블리드로
  바꾸고, 폰에서 0.36배로 보이는 점을 감안해 정보 글자는 34px 이상, 출처 줄은
  24px 이상으로 못 박았다. 검수도 390px 폭 축소본으로 한다.
- **공시 숫자가 맞아도 대본은 불합격이 될 수 있다.** 자동 파이프라인이 처음 뽑은
  편은 숫자가 전부 공시와 맞았는데 "뭘 말하고 싶은지 모르겠다"는 평을 받았다.
  교육 매출, 상표 등록 국가 수, 설립 지역 같은 **사실의 나열**이었기 때문이다.
  그래서 대본 앞에 `논지` 단계를 끼웠다. 공시로 증명할 수 있는 반직관 한 문장을
  먼저 정하고, 훅은 논지, 숫자는 증명, 약점은 논지의 그늘, 마무리는 제품으로
  돌아온다. 논지와 무관한 사실은 정확해도 뺀다. 시청자가 이미 아는 얘기는 공시상
  의외여도 탈락이다.
- **LLM이 쓴 대본보다 사람이 쓴 대본이 먼저 합격했다.** 구조를 확정하려고 대본을
  손으로 쓰고 같은 검사·원문 대조를 통과시키는 방식으로 몇 편을 검토했다. 합격한
  구조는 "정답을 숨긴 훅 → 회사 소개 → 정답 공개 → '결과는요?' → 제품 → 마무리"였다.
  설명이 많으면 재미없다는 평도 반영해, 숫자를 빠짐없이 넣지 않고 줄이는 쪽으로
  조정했다.
- **렌더 전에 정지 화면부터 본다.** 렌더 후 검수에서 발견한 문제(태그와 다른 사진,
  대사와 다른 연도, 멈춘 카운터)가 전부 정지 화면에서 보이는 것들이었는데, 그때마다
  전체 렌더를 다시 돌려 시간을 날렸다. 그래서 프리뷰 단계를 만들어 줄마다 시작·끝
  프레임을 먼저 검수하고, 승인 기록이 없거나 승인 뒤 에피소드가 바뀌면 렌더가
  멈추게 했다. 움직임과 소리는 정지 화면으로 못 보니 mp4 뒤 검수는 그대로 둔다.
  프레임 캐시는 장면 단위라 바뀐 장면만 다시 그린다.
- **끝부분 고지와 엔딩을 고정했다.** 광고·투자 관련 고지는 지키되 화면 하단이
  쇼츠 UI에 가려지는 점을 고려해 위치를 정했고, 모든 편에 같은 엔딩이 자동으로
  붙게 해 대본에는 적지 않는다.
- **공개 시각은 가설로 두고 시험했다.** 퇴근 시간대를 노린 저녁 공개와 아침 공개를
  번갈아 내보내 비교하기로 했고, 이후 조회수 정체를 따로 조사해 보고서로 남겼다.
  결론은 아직 확정하지 않았다.

## 배운 점

- **정확한 숫자는 합격선이 아니라 출발선이다.** 검증기가 모두 통과해도 "그래서
  뭐가 흥미롭냐"에 답하지 못하면 영상은 실패한다. 이 질문을 코드(논지 단계의
  증명 사실 개수 검사)와 문서(콘텐츠 최상위 룰, 테스트로 원문과 일치 확인)에
  각각 박아 두니 편마다 다시 판단하지 않아도 됐다.
- **LLM에 사실 목록만 주면 사실 나열이 나온다.** 대본 품질은 모델 성능보다 앞 단계에서
  "무엇을 증명할 것인가"를 정했는지에 달려 있었다.
- **분기 보고서의 숫자는 3개월 값이다.** 공시 API가 주는 분기·반기 금액은 해당
  분기 값이고 누적은 별도 필드다. 2분기 값을 "상반기"로 잘못 표기했다가 정정한
  뒤, 순위처럼 숫자가 많은 영상은 전 건 대조와 잠정실적 공시 확인을 거치게 했다.
- **시세 라이브러리는 장중에 현재가를 종가처럼 준다.** 종가 카드가 실제 종가와
  어긋난 것을 나중에 발견했다. 장중에 돌린 값은 종가로 쓰지 않는다.
- **자동 검사가 못 잡는 것이 있다.** 사진 속 제품 모델에 근거 없는 기술 라벨을
  붙인 실수, 제목과 맞지 않는 무료 영상 소재가 자동 선택된 일은 렌더 후 프레임을
  직접 보고서야 발견했다. 소재는 받은 뒤 제목과 프레임을 확인해야 한다.
- **플랫폼이 읽어 주는 값과 실제 설정은 다를 수 있다.** 업로드 API가 유료 프로모션을
  켜졌다고 읽어 주는데 관리 화면에서는 꺼져 있던 적이 있다. 원인은 모른다. 그래서
  업로드 보고에 "확인됨"이라고 쓰지 않고 화면 확인을 요청한다.
- **수익 조건은 공식 문서로 다시 확인한다.** 쇼츠 설명란 링크가 클릭되지 않는다는
  점, 제품 태그 조건이 구독자 수·파트너 프로그램 가입이라는 점은 공식 안내를 읽고
  나서 목표를 다시 잡았다. 제휴 링크 운영정책(미등록 매체 노출 금지 등)도 올리기
  전에 읽고 문구를 정했다.
