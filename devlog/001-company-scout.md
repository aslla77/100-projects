# 001 · company-scout — 공개 자료만으로 기업을 구조화하는 리서치 도구

> 회사명 하나를 입력하면, **공개된 자료만** 사용해 그 회사를 여섯 개 축으로 구조화하고
> 초심자도 이해할 수 있는 **출처 검증 리포트**로 만들어 주는 도구.

- **분야:** 리서치 자동화 / AI 에이전트 스킬
- **위험도:** Tier 0 (로컬 전용, 사용자 데이터 없음)
- **상태:** MVP 완료

## 왜 만들었나

기업을 조사할 때 정보가 블로그·뉴스·커뮤니티에 흩어져 있고,
어디까지가 **사실**이고 어디부터가 **추측**인지 뒤섞여 있다.
"근거 있는 사실"과 "근거 없는 인상"을 강제로 분리하고,
모든 문장에 출처를 달게 만드는 도구가 있으면 조사 품질이 올라간다는 가설에서 출발했다.

## 무엇을 만들었나

회사명 1개 → 아래 **여섯 축**으로 구조화한 리포트를 생성한다.

1. 회사 (개요·연혁)
2. 제품 / 서비스
3. 고객 / 시장
4. 재무 신호
5. 문제 / 리스크
6. 관련 회사

핵심 규칙은 **출처 강제**다.

- 모든 사실 주장에 공개 출처를 붙이고, 신뢰도를 **A / B / C** 등급으로 표기한다.
  (A = 공식·1차 자료, B = 검증된 매체, C = 커뮤니티·블로그 등 단서용)
- 확인하지 못한 것은 "**가설**" 또는 "**근거 부족**"으로 분리한다.
- 확인 일자를 함께 남겨, 시점에 따라 달라지는 정보를 구분한다.

같은 방법론을 **두 가지 형태**로 패키징했다.
하나는 OpenAI Codex 플러그인(`plugin.json` + 스킬 정의), 다른 하나는 미러링한 Claude Code 스킬.
동일한 방법론을 서로 다른 에이전트 런타임에 얹는 실험이기도 했다.

## 만드는 과정

- **리서치** — 출처 등급 체계(A/B/C)와 "사실 vs 가설" 분리 규칙을 먼저 설계했다.
- **기획** — 여섯 축 템플릿과 리포트 골격을 PRD-lite로 고정.
- **빌드** — 스킬 정의 + 구조 검증(structure-check) + zip 패키징 파이프라인.
- **검증** — 파일럿 회사 1곳으로 리포트 형식과 출처 강제가 실제로 작동하는지 확인.

## 배운 점

- **출처 강제는 "형식"이 아니라 "엔진"이다.** 모든 문장에 A/B/C를 붙이게 만들면,
  근거 없는 문장은 애초에 쓰기 어려워진다. 규칙이 결과 품질을 끌어올린다.
- **사실과 가설을 분리하는 칸을 물리적으로 나누면** 읽는 사람이 판단을 스스로 할 수 있다.
- **하나의 방법론, 두 런타임(Codex·Claude).** 방법론을 문서로 먼저 못 박아 두면
  런타임 이식이 쉬워진다.
