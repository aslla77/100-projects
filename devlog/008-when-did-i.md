# 008 · 언제했지 (When'd I) — 할 일을 관리하지 않고, 했던 날짜만 기억하는 앱

> 침대 시트를 언제 갈았더라. 정수기 필터는. 부모님께 전화한 게 언제였지.
> 할 일 목록을 만드는 대신, **마지막으로 한 날 하나만** 기록하고
> 오늘까지 며칠이 지났는지 보여주는 로컬 전용 앱.

- **분야:** iOS · Android · Flutter · 기록
- **위험도:** Tier 0 (서버·계정·개발자 데이터 수집 없음)
- **상태:** iOS · Android 출시, 10개 언어 (유료 단품, 인앱 결제·광고 없음). 최신 2.3.0은 2026-09-14 양 스토어에 심사 제출

## 왜 만들었나

할 일 앱은 "앞으로 할 일"을 관리한다. 그런데 생활의 꽤 많은 일은
마감이 없고, 주기도 애매하고, 잊고 지내다가 문득 궁금해진다.
"마지막으로 언제 했지?"가 질문의 전부인 일들 — 시트 교체, 필터 교체,
안부 전화, 화분 분갈이.

이걸 할 일 앱에 넣으면 두 가지가 어긋난다.

1. **미완료가 기본 상태가 된다.** 마감 없는 일은 언제나 "밀린 일"로 표시되고,
   목록은 죄책감의 목록이 된다.
2. **정작 필요한 정보가 없다.** 알고 싶은 건 "해야 한다"가 아니라
   "마지막이 언제였고, 보통 얼마 만에 하는가"다.

그래서 방향을 뒤집었다. 계획·마감·체크리스트를 전부 빼고,
**한 일의 날짜만 쌓는다.** 기록이 쌓이면 "지난 날수"와 "평소 간격"이
자연스럽게 드러나고, 그게 다음 행동의 신호가 된다.

## 무엇을 만들었나

- **지난 날수** — 항목마다 마지막으로 한 날부터 며칠 지났는지 한눈에 보인다.
- **간격이 보이는 타임라인** — 세로 시간축에서 **점 사이 거리가 실제 날짜 간격**이다.
  뜸했던 구간은 길게 비고, 자주 한 구간은 촘촘하다. 숫자를 읽기 전에 간격이 먼저 보인다.
- **위젯·잠금 화면 기록** — 앱을 열지 않고 홈 화면·잠금 화면에서 바로 "오늘 했음"을 남긴다.
  기록 마찰이 탭 한 번을 넘으면 이런 앱은 유지되지 않는다.
- **기록별 사진 1장 + 메모** — 필터를 갈았으면 갈아 끼운 필터 사진을 남기는 식.
- **로컬 전용 + 자동 보관** — 서버도 계정도 없다. 백업은 JSON 파일로 내보내고,
  iOS는 사용자 본인의 iCloud에 한 벌을 자동 보관해 재설치 때
  "이전 기록을 발견했어요"라고 물어본 뒤 복원한다.
- **유료 단품** — 한 번 사면 끝. 인앱 결제·구독·광고 없음. 10개 언어(한·영·일·중 + 독·프·이·스·태·포, 뒤의 6개는 1.1.0에서 추가).

## 만드는 과정

- **"기록이 사라지지 않는다"를 최우선 요구사항으로 뒀다.** 이런 앱의 가치는
  기록이 3년쯤 쌓였을 때 나온다. 그래서 앱 삭제·기기 변경 시나리오를 먼저 설계했다 —
  JSON 백업·복원, iCloud 자동 보관, 재설치 감지 후 복원 안내까지가 한 세트다.
- **스토어 제출을 API 파이프라인으로 만들었다.** 버전 생성 → 빌드 연결 →
  4개 언어 What's New 입력 → 심사 제출까지 App Store Connect API로 처리한다.
  버그픽스 업데이트를 내는 부담이 확 줄었고, 이 파이프라인은 이후 프로젝트가 그대로 물려받았다.
- **홍보 글에 지어낸 경험담을 쓰지 않기로 정했다.** SNS 소개 글을 만들다 보면
  "3년 만에 필터를 갈았다는 A씨" 같은 가상 사례가 자꾸 만들어진다.
  실제 경험, 질문형, 상태 묘사만 쓰는 것을 원칙으로 못 박았다.

## 배운 점

- **빼는 것이 컨셉이 될 수 있다.** 이 앱의 기획은 기능 추가가 아니라 제거의 연속이었다 —
  마감 없음, 알림 기본 꺼짐, 목표 없음. "할 일 앱이 아니다"라는 문장이
  스토어 설명에서 가장 힘이 셌다.
- **시각화는 축의 선택이 절반이다.** 목록 대신 "점 간격 = 실제 간격" 타임라인을
  선택한 순간, 별도 통계 화면 없이도 패턴이 보였다.
- **로컬 전용 앱의 약점은 백업이고, 백업의 약점은 사용자다.** 수동 백업만 두면
  아무도 하지 않는다. 자동 보관 + 복원 시점의 명시적 확인이라는 조합이
  "몰래 클라우드에 올리는 앱"이 되지 않으면서 데이터를 지키는 균형점이었다.

## 출시 후

2026-09-05부터 09-14까지 열흘 사이 다섯 번 업데이트했다.

- **1.1.0 — 6개 언어 추가.** 독일어·프랑스어·이탈리아어·스페인어·태국어·포르투갈어를 더해
  총 10개 언어가 됐다. 앱 화면뿐 아니라 스토어 등재문·업데이트 노트까지 전 계층에 반영했다.
- **1.1.1 — 사진 중복 저장 수정.** 앨범에서 고른 사진이 기기 앨범에 한 번 더 저장돼
  사진 앱 검색에 같은 사진이 두 장 잡히던 문제를 고쳤다.
- **2.0.0 — 사진·보고서 개편.** 기록 하나에 사진을 여러 장 붙이고, 저장 전에 다듬는
  화면을 새로 넣었다. 사진첩에는 위아래로 기록, 좌우로 사진을 넘기는 피드 뷰어를 넣고,
  보고서 화면을 개편했다.
- **2.1.0 — 다중 날짜·감각 피드백.** 다른 날짜를 여러 개 한 번에 추가하는 달력 시트,
  소리·햅틱, Android 백업 복원 시 글자가 깨지던 버그 수정.
- **2.2.0 — 중복 항목 버그와 합치기.** 입력창에서 엔터를 치면 같은 이름 항목이 하나
  더 생기던 버그를 고치고, 이미 생긴 중복을 합치는 기능과 홈에 지난 기록도 표시하는
  설정을 넣었다.
- **2.3.0 — "사전" 화면 리뉴얼.** 탭을 [사진첩/달력/카테고리]로 바꾸고 가나다 순 탭을
  뺐다. 달력 탭은 한 달 격자와 연간 보기를 오간다. 사진첩엔 검색과 메모 숨기기 토글을
  추가했다.

**번역은 3단계를 거친다.** 한 모델이 초벌 번역을 하고 더 강한 모델이 검수한 뒤,
앱 안에 실제로 쓰인 화면 이름과 대조하는 단계를 거친다. 이 마지막 단계에서
일본어·중국어·태국어 화면 이름이 여러 차례 바로잡혔다 — 같은 개념이라도 언어마다
자연스러운 단어가 달랐다.

**복수형 함정도 하나 걸렸다.** 유니코드 CLDR 복수형 규칙에서 프랑스어와 포르투갈어는
개수 0이 "one" 범주로 분류된다[1]. "one" 분기라고 숫자를 생략하면 0일 때 문장이
어색해진다. one 분기에도 숫자를 그대로 넣도록 고쳤다.

**스토어 파이프라인에서 두 가지를 새로 배웠다.** Google Play는 앱 번들이 60MB를
넘으면 단발 업로드가 실패해 이어올리기(resumable upload) 방식으로 바꿔야 했다[2].
App Store Connect는 심사 대기 중에 릴리즈 계획이 바뀌면서, 같은 버전 레코드를
다음 빌드로 옮겨 붙이는 방식으로 대응했다.

**SNS는 "완료 목록" 시리즈를 올렸다.** 끝낸 일을 기록하는 게 왜 효과가 있는지를
심리학 연구 여러 개로 짚는 캐러셀이다 — 진행의 원리(아마빌), 자기효능감(반두라),
자이가르닉 효과, 프랭클린의 하루 질문 등. 영어판도 따로 만들었고, 프로모션 코드
배포 이벤트도 함께 진행했다. 두 원칙은 계속 지켰다 — 홍보 글에 지어낸 경험담을
쓰지 않는다, 그리고 홍보 문구를 열 때 앱 자체를 부정하지 않는다(문제로 열고
도구는 해결책으로만 등장시킨다).

**배운 점.** "기능을 빼는 게 컨셉"이었던 앱인데도 출시 후 열흘 사이 기능이 꽤
늘었다. 추가할 때마다 기준은 하나였다 — 그래도 "한 일을 날짜만 기록하는 앱"인가.
